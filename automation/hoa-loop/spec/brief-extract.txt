1. Project Overview
Project Name: Homeowners Association Information System (HOA IS)
Client: Southville Phase I Homeowners Association
Location: Brgy. Inocencio, Trece Martires City, Cavite
Type: Web-Based Information System
Duration: March 2026 – December 2026
Problem Statement
The HOA of Southville Phase I currently operates using manual, paper-based processes for managing homeowner records, collecting association dues, handling complaints and requests, and issuing community certificates. This results in slow data retrieval, high risk of financial recording errors, difficulty tracking payment statuses, inefficient complaint/request resolution tracking, no centralized platform for community announcements, and no audit trail for administrative actions.
Proposed Solution
A centralized, web-based Homeowners Association Information System built entirely on Laravel 12 with a multi-panel Filament v3 architecture. Every authenticated role — HOA Admin, HOA Staff, and Homeowner — gets its own dedicated Filament panel with its own dashboard, navigation, and scoped resources. Only the public-facing Landing Page remains a separate React application.
Landing Page — public-facing, GSAP-animated marketing page (React.js + Vite)
Admin Panel (/admin) — Filament panel for HOA Admin, full system oversight
Staff Panel (/staff) — Filament panel for HOA Staff, operational tasks only
Homeowner Panel (/homeowner) — Filament panel for the Homeowner role, self-service records, scoped strictly to the logged-in homeowner's own data
All three back-office panels are separate Filament Panel Provider instances sharing one Laravel codebase, one database, and one set of models — but each with its own route prefix, its own login screen, its own navigation menu, and its own dashboard widgets, filtered by Filament Shield permissions and Eloquent-level scoping.
Payment handling covers recording and monitoring of dues by HOA Admin/Staff; homeowners may upload proof of payment for staff verification, but the system does not process real-time transactions through a third-party payment gateway at this stage.

3. System Architecture
The system now has four distinct front doors sharing one Laravel backend: a public React Landing Page, and three independent Filament panels — Admin, Staff, and Homeowner — each with its own login, navigation, and dashboard.
Layer
Surfaces
Browser Layer
Landing Page (React + GSAP) · Admin Panel (Filament) · Staff Panel (Filament) · Homeowner Panel (Filament)
Application Layer
Laravel 12 — Routing → Middleware → Filament Panel Providers → Controllers/Livewire → Services → Models
Cross-cutting
Form Requests · Policies & Gates · Observers · Queues & Jobs · Mail (Google SMTP) · Exports
Data Layer
MySQL 8.0+ — users, roles/permissions, homeowners, payments, complaints, requests, announcements, certificates, dues, audit logs
Routing Strategy
/ → Landing Page (React SPA served via Vite)
/admin → Filament Admin Panel (HOA Admin only)
/staff → Filament Staff Panel (HOA Staff only)
/homeowner → Filament Homeowner Panel (Homeowner role only)
/api/contact → Laravel API route used solely by the Landing Page contact form
Each Filament panel is registered as its own Panel Provider (AdminPanelProvider, StaffPanelProvider, HomeownerPanelProvider) with its own path(), its own guard, its own login page, and its own set of registered Resources/Widgets/Pages. A user authenticated in one panel is not automatically authenticated in another; Filament's per-panel auth guards keep the three surfaces fully isolated even though they share the same users table.

Implementation

9. Authentication Module
Authentication is now Filament-native across all three roles. There is no more React/Axios/Sanctum login flow — HOA Admin, HOA Staff, and Homeowner each log in through their own panel's native Filament login screen, each backed by its own auth guard.
9.1 HOA Admin Login
Route: /admin/login (Filament native)
Filament's built-in authentication, admin guard
Google SMTP email for password reset
Rate limiting: max 5 failed attempts before temporary lockout (Laravel built-in throttle)
Session-based authentication
9.2 HOA Staff Login
Route: /staff/login (Filament native, separate panel from /admin)
Filament's built-in authentication, staff guard
Same rate-limiting and session-based rules as the Admin Panel
A Staff account cannot log into /admin, and an Admin account is not automatically granted a Staff Panel session — each panel checks canAccessPanel() independently
9.3 Homeowner Login
Route: /homeowner/login (Filament native — replaces the former React/Sanctum SPA login)
Filament's built-in authentication, homeowner guard, session-based like the other two panels
"Forgot Password" link -> Filament's built-in reset flow, email-based via Google SMTP
Redirect to /homeowner (Homeowner Dashboard) on success
SweetAlert2 toast (via Filament hook) on failed login
9.4 Password Reset Flow (all three panels)
1. User clicks "Forgot Password" on their panel's login screen
2. Enters registered email
3. Laravel sends a signed reset link via Google SMTP
4. User clicks link -> Filament's native reset-password page for that panel
5. Enters and confirms new password (match validation)
6. Success notification -> redirect to that panel's login
9.5 Email Verification
New Homeowner accounts require email verification, using Laravel's built-in email verification sent via Google SMTP
The Homeowner Panel shows a "Verify Your Email" banner (Filament notification banner) if not yet verified
9.6 Universal Auth Rules
CSRF protection on all forms (Livewire/Filament handles this natively)
All auth routes rate-limited, per panel
Passwords validated using Laravel's Password::defaults() (min 8, mixed case, numbers, symbols)
Passwords hashed with bcrypt (Laravel default)
No plain-text passwords stored or displayed

13. Module Breakdown
Module 1: Homeowner Records Management
Access: HOA Admin (Full CRUD, /admin), HOA Staff (Create/Edit/View, /staff), Homeowner (View/Edit own, /homeowner).
Features
Complete homeowner profile management: Name fields, Sex, DOB, Age (auto), Contact Number, Email, Profile Photo, Lot/Block/Street/Phase, Move-In Date, Occupancy Type, Emergency Contact, Account Status
Soft delete with restore capability
Status management: Active, Inactive, Delinquent (system-flagged when payments are overdue)
Each homeowner record linked to a users account with a canAccessPanel() rule limiting them to /homeowner
Validations
Lot Number + Block Number combination must be unique; Email must be unique across system
Contact Number: exactly 11 digits, stored as string
Move-In Date must not be a future date
Profile photo: JPEG/PNG/WEBP only, max 2MB, stored with unique filename
Module 2: Association Dues & Payment Management
Access: HOA Admin (Full, /admin), HOA Staff (Create/Edit payment records, /staff), Homeowner (View own, upload proof of payment, /homeowner).
2A: Dues Schedule Management (Admin/Staff)
Create billing periods (Monthly, Annual, Special Assessment) with Name, Amount, Due Date, Period, Type, Description
System auto-generates individual payment records for each active homeowner when a dues schedule is created (via Laravel Job dispatched to Queue)
Amount stored as DECIMAL(10,2); cannot delete a dues schedule that has linked payment records, only deactivate
2B: Payment Recording (Admin/Staff)
Record payment for a specific homeowner's dues record: Homeowner, Dues Schedule, Amount Paid, Payment Method (Cash/GCash/Bank Transfer/Check), Reference Number, Receipt Number, Notes
System calculates Balance = Amount Due − Amount Paid; auto-updates status: Paid, Partial, Unpaid
System flags Overdue when Due Date passes and status is not Paid; daily scheduled command checks overdue records and sends email notification
Receipt PDF auto-generated and downloadable
2C: Homeowner View (Homeowner Panel)
Homeowner views own payment history in the /homeowner Payments Resource; outstanding dues displayed prominently
Payment proof upload (for offline/bank/e-wallet payment verification): JPEG/PNG/PDF, max 5MB — stored in private storage, reviewed by Staff. No live payment gateway is integrated at this stage.
2D: Delinquency Tracking
Automated: homeowner status flips to "Delinquent" after X consecutive unpaid months (configurable in System Settings)
Delinquency report available in Reports module; email notification to delinquent homeowners via Google SMTP
Module 3: Complaint & Request Management
Access: HOA Admin (Full, /admin), HOA Staff (Full operational, /staff), Homeowner (Submit/View own, /homeowner).
3A: Complaint Submission (Homeowner Panel)
Fields: Subject, Category, Priority, Description, Attachments (max 3 files, 5MB each)
Review step before submission; SweetAlert2 confirm dialog
Email notification to HOA Staff via Google SMTP on new complaint
3B: Complaint Management (Admin/Staff Panels)
Update status: Open -> Under Review -> Resolved / Rejected / Closed (validated transitions)
Resolution notes required when resolving or rejecting; optional assignment to staff member
Email notification to Homeowner on status change
3C: Request Submission (Homeowner Panel)
Request types: Certificate of Residency, Certificate of Good Standing, Community Clearance, Repair/Maintenance, Other
Fields: Type, Subject, Description, Supporting Documents; review step + confirmation
3D: Request Management (Admin/Staff Panels)

14. Universal Form Rules
All forms across all four surfaces (Admin Panel, Staff Panel, Homeowner Panel, Landing Page contact form) implement the following rules.
14.1 Password Fields
Eye toggle on all password inputs; match validation before submission
Laravel Password::defaults() rule: minimum 8 characters, mixed case, numbers, symbols
Fields cleared on validation error; never displayed in plain text post-submission
14.2 Name Fields (First, Middle, Last)
Auto-capitalize first letter of each word; reject numbers/special characters (except apostrophes and hyphens)
Trim leading/trailing spaces, prevent multiple consecutive spaces; validated on frontend and backend
14.3 Suffix Field
Optional dropdown: Jr. / Sr. / II / III / IV / N/A; no free-text entry
14.4 Sex Field
Options: Male / Female / Prefer not to say; dropdown in full forms, radio buttons in compact forms
14.5 Contact Number
11 digits exactly, numeric only; placeholder 09XXXXXXXXX; stored as VARCHAR(11)
14.6 Date of Birth & Age
Date picker, max date = today; auto-calculates age on change; backend recalculates age, ignores frontend-submitted value
14.7 Email Address
Lowercase before save, trim spaces; real-time duplicate check on blur (debounced 400ms)
Unique DB constraint + Laravel unique validation; ignores current record's email on edit
14.8 Required / Optional Fields
Required: red asterisk label; Optional: '(Optional)' text; backend Form Request classes are authoritative
14.9 Input Sanitization
Trim all text inputs; escape all output in Blade with {{ }}; Filament/Livewire escapes rendered content by default
14.10 Registration Review Step
Summary card before final submit; disable submit on click, re-enable on failure; duplicate submit prevention
14.11 SweetAlert2 Usage
All delete/destructive actions require confirmation, in every panel via the shared Filament SweetAlert2 hook
Submit confirmations for important actions; toasts auto-dismiss after 3 seconds
14.12 Modal Reset Logic
All fields, validation errors, messages, file previews, and states cleared on modal cancel/close/dismiss
14.13 CSRF Protection
All forms use Laravel/Livewire's native CSRF protection; the Landing Page's Axios contact-form request sends an X-CSRF-TOKEN header from a meta tag
14.14 File Uploads
MIME check on backend, not just extension; max size enforced (2MB photos, 5MB documents)
Unique filenames via Str::uuid(); sensitive files in storage/app/private/, served via signed URLs
14.15 Dropdown Defaults
Default: "Select an option" — never a real DB value as placeholder; dependent dropdowns reset on parent change
14.16 Numeric / Currency
DECIMAL(10,2) for all monetary values, no floating-point types for money
Frontend displays formatted (e.g., ₱1,250.00) but submits raw numeric value
14.17 Dates / Times
End date never before start date; consistent display format: MMM DD, YYYY
14.18 Status Fields
Always dropdown or controlled action, never free-text; defined as PHP enums or string constants
14.19 Delete Actions
Soft deletes for Homeowners, Payment Records, Complaints, Requests, Announcements, Certificates
Hard deletes: Audit Logs only (intentionally immutable)
14.20 Tables (Filament Tables across all three panels)
Server-side pagination, search, sort, filter on every major table
CSV export per table where applicable; responsive layout
15. Security Implementation
Authentication Security
bcrypt password hashing (Laravel default)
Rate limiting on login: throttle:5,1 (5 attempts per minute) on all three panel login routes
Signed password reset tokens with 60-minute expiry
Session-based authentication for Admin, Staff, and Homeowner — each panel uses its own auth guard so a hijacked Homeowner session cannot be reused against /admin or /staff
Authorization Security
Laravel Policies on every Controller/Livewire method; Filament Shield generates and enforces per-panel policies
Middleware groups: auth, verified, role:..., applied per panel
Homeowner Panel resources are globally scoped so a Homeowner can only ever query their own data — this is enforced at the Eloquent query layer, not just hidden in the UI
Input Security
All inputs sanitized and validated server-side
SQL injection prevention: Eloquent ORM with parameterized queries
XSS: Blade {{ }} escaping, Livewire/Filament safe rendering by default; mass assignment protection via $fillable
File upload: MIME verification, unique stored names, private storage for sensitive files
Infrastructure Security
.env file never committed to version control; HTTPS enforced in production
Sensitive config via environment variables; APP_DEBUG=false in production
Database: least-privilege MySQL user for application
Rate Limiting
Login: 5 attempts/minute per panel; Password Reset: 3 requests/minute
API endpoints (Landing Page contact form only): throttle:3,1

Phase 1: Project Setup & Architecture (Week 1–2)
Initialize Laravel 12 and the standalone React+Vite Landing Page project; install Filament, Spatie Permission, Spatie Activity Log, Laravel Excel, DomPDF; configure MySQL, Git, Google SMTP; run base migrations; seed roles (HOA Admin, HOA Staff, Homeowner) and an initial Admin account; scaffold three separate Filament Panel Providers (Admin, Staff, Homeowner) with their own paths, guards, and brand-color theme configuration.

Filament native login for all three panels (/admin, /staff, /homeowner), each on its own guard; password reset flows per panel; email verification for Homeowner accounts; canAccessPanel() checks so accounts can only reach their assigned panel; rate limiting.

Phase 4: Dues Schedules & Payment Management (Week 4–5)
dues_schedules and payment_records migrations/models; DuesScheduleResource, PaymentRecordResource in Admin/Staff panels, plus a scoped Payments resource in the Homeowner panel; Job for auto-generating payment records; daily overdue-detection command; receipt PDF generation; homeowner payment proof upload; delinquency auto-flagging.
Phase 5: Complaint & Request Management (Week 5–6)
complaints and requests migrations/models; management resources in Admin/Staff panels; submission resources with review steps in the Homeowner panel; status transition logic; file attachment handling (private storage, signed URLs); email notifications.
Phase 6: Announcements Module (Week 6)

Phase 7: Certificate & Document Issuance (Week 7)

Phase 8: Reports & Exports (Week 7–8)
